# Using your own character models

The five characters are generated by `AnimatronicFactory`, which is a reasonable
placeholder and nothing more. It builds boxes and spheres on a bone hierarchy. It will
never look like a model somebody sculpted.

So the project takes downloaded models, and this is how.

---

## The short version

1. **Tools → Grotto → Import a Character Model**
2. Pick which character you are replacing.
3. Drag the model file in.
4. Check the **Head** binding. Fix anything else that looks wrong.
5. Set the rotation if it is facing away from you.
6. Save.

Press Play. That is the whole process; nothing else in the project changes.

A character with no imported model is generated exactly as before, so replacing one of
the five and leaving the other four is a perfectly normal state to be in.

---

## Where to get models

| Source | What is there | Notes |
|---|---|---|
| **Sketchfab** | Thousands of animatronic, mascot-robot and fursuit-robot models | Filter by **Downloadable**, then by licence. The single best source |
| **itch.io** | Asset packs, some game-ready, some free | Search "animatronic" or "robot character" |
| **Unity Asset Store** | Rigged, game-ready, correctly scaled | The least work per model; usually paid |
| **The FNAF fan-model community** | Exactly what you are after | DeviantArt, Models Resource, the fan-game Discords |
| **Blender Market / CGTrader / TurboSquid** | Commercial, high quality | Check the licence permits game use |
| **Mixamo** | Not characters, but free auto-rigging | Upload an unrigged model, get a rigged one back. The binder handles Mixamo naming perfectly |

### Which format

Sketchfab usually offers four or five. Take **GLB**, at the largest texture size listed.

| Format | Verdict | Why |
|---|---|---|
| **GLB** | **Take this** | One self-contained binary — geometry, skeleton and textures in a single file. Nothing to go missing |
| **glTF** (`.gltf`) | Works | Arrives as a `.gltf` plus a `.bin` plus a folder of images. A broken texture path is the usual reason an import comes in grey. Keep the whole folder together |
| **FBX** | Take this if no GLB | Unity's native format, no package needed |
| **OBJ** | Last resort | No skeleton. The model works but never turns its head or opens its mouth |
| **USDZ** | Never | Apple AR format. Unity will not read it |

On texture size: take the biggest. You can downscale in Unity's import settings and you
cannot upscale, and a few extra megabytes on disk costs nothing.

On "Original format" versus "Converted": the original is what the author uploaded and is
the highest fidelity, but it is whatever they happened to export — sometimes a zip with
external textures and odd paths. Sketchfab's converted GLB is a clean re-export that
preserves the skinning. **Start with the converted GLB.** If the rig comes through wrong,
fall back to the original.

### glTF needs a package — this catches everybody

**Unity does not import `.glb` or `.gltf` out of the box.** It reads FBX, OBJ, DAE and a
few others natively; glTF needs `com.unity.cloud.gltfast`, which is in this project's
`Packages/manifest.json` already.

The reason this is worth a heading: **the failure is silent.** Drop a `.glb` into a
project without the package and Unity ignores the file completely — no error, no warning,
it simply does not appear as a model asset. It looks like you did something wrong.

If it has not resolved, the import window detects it and has a one-click install button,
or *Window → Package Manager → + → Add package by name →* `com.unity.cloud.gltfast`.

### What else to look for

**Rigged, if you can get it.** A rigged model gets head tracking, a working jaw and the
servo idle. An unrigged one is a statue that slides between rooms.

**Any scale, any units.** Genuinely does not matter. The importer measures the model and
scales it to the character's authored height, so a Source-ported model at 1:52 and a
Blender export at 1:1 both come out the right size.

**Check the licence, then record it.** CC-BY ("CC Attribution") is the common one on
Sketchfab and it means you may use it commercially as long as you credit the author.
Sketchfab's download dialog has a **COPY CREDITS** button that produces exactly the right
text — paste that straight into the importer's credit box.

### On ripped assets

Fan games are fine and there are thousands of them. What is *not* fine is committing
files extracted from a shipped game into a public repository — not for moral reasons but
practical ones: it is the one thing that will get a repo taken down, and it means you can
never put the project on itch. Keep extracted assets out of git if you use them. The
`.gitignore` already excludes `Assets/Game/Resources/Cast/Models/`.

## What the importer does

### Scale and grounding

Measures the model's renderer bounds and scales it so its height matches
`AnimatronicModelSpec.height` — 2.05m for Barty, 1.55m for Vesper, and so on. Then puts
its lowest point on the floor.

Height rather than a scale factor, because height is what the game actually uses: the
jumpscare frames on the head, the collider is sized from it, and a character that is
nominally 2.05m has to be 2.05m for the camera move to land. What the exporter thought a
unit was is not interesting.

### Bone binding

`RigBinder` matches whatever the bones are called to the ones the game drives. It
normalises away the decoration — namespaces, `DEF-`/`ORG-`/`mixamorig:` prefixes, side
markers, trailing numbering — and scores the remainder against a keyword table.

Verified against every convention in common use:

| Rig | Head | Core bones | Limbs |
|---|---|---|---|
| Mixamo | ✅ | 5/6 | 14/14 |
| Blender / generic | ✅ | 6/6 | 14/14 |
| Rigify (`DEF-` bones) | ✅ | 6/6 | 14/14 |
| Source (`ValveBiped.Bip01_*`) | ✅ | 5/6 | 14/14 |
| 3ds Max Biped (`Bip01 *`) | ✅ | 4/6 | 14/14 |
| Hand-named fan rig (`l_arm_upper`) | ✅ | 6/6 | 14/14 |
| Static mesh, no skeleton | ✅ (proxy) | 1/6 | 0/14 |

The 5/6 rows are missing a jaw, because Mixamo and ValveBiped rigs genuinely do not have
one. Two things beyond the keyword table:

* **The spine chain is filled from the hierarchy** when names do not give it away. Every
  biped has hips, spine, chest and neck stacked in that order whatever they are called —
  Rigify's pelvis is `DEF-spine` — so an empty slot takes the parent of the bone below it.
* **One bone, one slot.** A rig whose chest bone is called `spine2` would otherwise bind
  it to both Chest and Spine, and the servo animator would then rotate the same transform
  twice a frame from two directions.

**Only the Head matters.** Everything else is optional and degrades cleanly:

| Missing | Consequence |
|---|---|
| Jaw | The character does not open its mouth |
| Neck, Chest, Spine, Hips | No idle servo sway |
| Arms, legs | No limb jitter |
| Head | A proxy is planted at 90% height — no head tracking, but the camera and the jumpscare still frame correctly |

The import window lists every binding with a dropdown, so a wrong guess is one click from
being right rather than a mystery.

### Materials

Almost every model on the internet ships Standard-shader materials, which under URP
render as **flat magenta**. This is the single most common reason an import appears not
to work. The importer moves the base colour and albedo map onto URP Lit for you.

It only touches shaders URP cannot render — `Standard`, `Legacy Shaders/*`, `Mobile/*`,
`Autodesk Interactive`. A model that already ships URP or a custom shader is left exactly
as its author made it.

A glTF or GLB imported through glTFast already arrives with pipeline-correct materials,
so the conversion pass sees nothing to do and leaves it alone. This mostly matters for
FBX, which is where Standard materials come from.

### Eyes

The eye glow is not decoration. It is how you identify a character at twenty metres in an
unlit cavern, and the jumpscare is framed around it.

If the model has geometry named `eye`, `pupil`, `iris` or `sclera`, that gets the
emissive material in the character's colour. If it has none, two lamps are added to the
head, sized from the head's own bounds. Turn it off in the import settings if your model
already glows.

## The two things it cannot guess

Both live in the settings asset saved beside the prefab, so changing them never means
re-importing.

**Which way it faces.** Models face `-Z` about as often as `+Z` and there is no reliable
way to tell from geometry. If the character has its back to you, set rotation Y to 180.
The window has buttons for the four quarter turns and for Z-up exports (Blender's default
FBX, and most CAD), which need X = -90.

**Where the added eye lamps sit.** Only relevant when the model has no eyes of its own.
Nudge them in the prefab.

## Credits

The import window writes `Assets/Game/Resources/Cast/Models/CREDITS.md`, rebuilt from each
model's settings asset every time you import. It cannot drift out of date, and it is one
place to look when you need to credit everybody.

**Fill in the attribution box.** It takes ten seconds while you still have the download
page open, and a project full of models whose origin nobody recorded is a project that can
never be released.

## Troubleshooting

| Symptom | Cause |
|---|---|
| **The .glb does not appear in Unity at all** | No glTF importer. See the section above — the failure is silent, which is why it looks like something else |
| **Magenta character** | Materials did not convert. Re-import with *Convert materials to URP* on, or set the shader to URP Lit by hand |
| **Grey / untextured** | A `.gltf` whose external textures did not come with it. Use the GLB instead |
| **Facing away from you** | Rotation Y = 180 in the settings asset |
| **Lying on its side** | Z-up export. Rotation X = -90 |
| **Enormous or microscopic** | Auto-fit is off, or the model has no renderers to measure. Check the import settings |
| **Sunk into the floor** | The model has a stray renderer far below the body — a ground plane or a shadow quad is the usual culprit. Delete it from the source |
| **Head does not turn** | No head bone was bound, so a proxy is in use. Pick the real one in the import window |
| **Every bone is called `Object_4`** | Some Sketchfab GLB conversions flatten node names. The binder finds nothing and plants a proxy; either bind Head by hand in the window, or download the original format instead, which keeps the author's names |
| **Parts you do not want are visible** | Plenty of models ship variant or optional meshes that are all enabled at once. Open the saved prefab and disable or delete them — the importer does not touch mesh visibility |
| **Eyes in the wrong place** | Move them in the prefab — they are plain child objects of the head |
| **Nothing changed after importing** | The model has to be at `Resources/Cast/Models/<id>`, where `<id>` is the character's id (`barty`, not `Bartholomew Bellows`). The window handles this; a hand-placed file may not |

To compare against the generated character, turn off **Prefer imported** on the
`AnimatronicModelSpawner`, or just delete the prefab — *Remove it* in the import window
does that and leaves your source file alone.
